# Adversarial wire conformance corpus for src/parser.c in RESPONSE mode.
#
# Run by tests/test_conformance.c (the Makefile passes this file's path).
# Every vector is the EXACT byte sequence a server puts on the socket,
# spelled with escapes so no literal CR, LF or NUL ever appears in this file
# and no editor or git CRLF rule can silently rewrite a vector.
#
# The format, the escape grammar and the verdict vocabulary are documented
# in conformance/format.md. Each case is three lines, blank-line separated:
#   name:   <the rule or property this vector exercises>
#   expect: accept none|cl=<n>|chunked|until-eof [body=<n>] [excess=<n>]
#           [status=<n>] | reject SYNTAX|FRAMING|LIMIT | incomplete
#   wire:   <escaped response bytes>
#
# These are PARSER verdicts: framing, status-line and header grammar only.
# Every vector runs against a default-limits parser in its default mode
# (no HEAD or CONNECT context), and is asserted at several chunk
# fragmentations with split equivalence.

# ===== acceptance: the baseline shapes the corpus then bends

name: a plain 200 with Content-Length framing is complete when the body is
expect: accept cl=5 status=200
wire: HTTP/1.1 200 OK\r\nContent-Length: 5\r\n\r\nhello

name: Content-Length: 0 completes at the header terminator
expect: accept cl=0
wire: HTTP/1.1 200 OK\r\nContent-Length: 0\r\n\r\n

name: a Content-Length with leading zeroes is 1*DIGIT and is accepted
expect: accept cl=7
wire: HTTP/1.1 200 OK\r\nContent-Length: 007\r\n\r\n0123456

name: Content-Length wrapped in HTAB OWS is trimmed and accepted
expect: accept cl=2
wire: HTTP/1.1 200 OK\r\nContent-Length:\t2\t\r\n\r\n{}

name: body bytes are opaque: NUL and high bytes pass through untouched
expect: accept cl=4
wire: HTTP/1.1 200 OK\r\nContent-Length: 4\r\n\r\n\0\xff\x80a

name: a reason phrase may carry spaces, HTAB and high bytes
expect: accept cl=0 status=503
wire: HTTP/1.1 503 D\xc3\xa9sol\xc3\xa9,\tservice saturated\r\nContent-Length: 0\r\n\r\n

name: an empty reason is accepted when the space before it is on the wire
expect: accept cl=0 status=200
wire: HTTP/1.1 200 \r\nContent-Length: 0\r\n\r\n

name: Connection tokens are data to the parser, not framing
expect: accept cl=2
wire: HTTP/1.1 200 OK\r\nConnection: keep-alive\r\nKeep-Alive: timeout=5, max=99\r\nContent-Length: 2\r\n\r\n{}

name: a weird but grammatical Connection list does not change the verdict
expect: accept cl=0
wire: HTTP/1.1 200 OK\r\nConnection: Keep-Alive, X-Weird-Token, close\r\nContent-Length: 0\r\n\r\n
