# Resolver provider and supervised-process plan

Status: implemented private seam; supervised provider design only. This is not
a public ABI or a claim that H2 can forcibly cancel `getaddrinfo()`.

## Why DNS is not in Maelys System

Maelys System owns socket and reactor mechanics. A resolver introduces host
names, address-result policy, worker supervision, an IPC protocol and platform
resolver behavior. Putting `getaddrinfo()` behind a System thread would still
leave the call uninterruptible and would turn a scheduling wrapper into a false
deadline guarantee. DNS therefore remains above System.

## Private seam delivered now

```text
HTTP POSIX transport (owner/reactor thread)
          │ start(host, port, request-id, deadline)
          ▼
private resolver provider
          │ borrowed notification fd
          ▼
System fd_wait      ──► nonblocking take()
          │
          ▼
validated numeric endpoints, at most 32
```

The seam in `src/resolver_internal.h` is injectable but deliberately private.
It has these invariants:

- every request has a nonzero 64-bit identity generated by the parent;
- `start` copies or otherwise owns every input it needs;
- the borrowed notification descriptor becomes readable only for a terminal
  response; the reactor thread never blocks in a provider;
- `take` is nonblocking and returns a response identity plus no more than 32
  fixed IPv4/IPv6 endpoints;
- the parent rejects an identity mismatch, invalid family, changed port,
  invalid scope, empty response or excess count before creating a socket;
- `cancel` may be called concurrently with provider work;
- `HARD_CANCEL` means the underlying operation has stopped and been reaped
  before `cancel` returns; `HARD_DEADLINE` means no work survives its deadline;
- `SUPERVISED_PROCESS` is valid only together with both hard guarantees.

The compatibility provider has guarantee mask zero. Its four detached threads
and 64-entry queue are bounded, and cancellation is memory-safe, but the OS/NSS
call may outlive the exchange. It is named `posix-getaddrinfo-compat` so this
limitation remains observable in diagnostics and tests.

## Target process topology

```text
HTTP owner thread
   │ request MHRP draft frame on private fd
   ▼
resolver supervisor
   ├── slot 1 ── one serial worker process ── getaddrinfo
   ├── slot 2 ── one serial worker process ── getaddrinfo
   ├── slot 3 ── one serial worker process ── getaddrinfo
   └── slot 4 ── one serial worker process ── getaddrinfo
          │
          ├── result frame ──► notification fd ──► validated take
          └── timeout/cancel/crash ──► kill + bounded reap + replace slot
```

One worker handles one query at a time. Cancellation or deadline expiration
kills and reaps that worker, then creates a clean replacement. This makes the
guarantee physical even when libc, NSS, mDNS or a plugin is stuck. A persistent
multi-query worker would not allow one blocked `getaddrinfo()` to be cancelled
without also invalidating unrelated queries.

## Draft IPC envelope

The following is an implementation target, not a frozen wire standard:

```text
u32 frame_bytes_be       <= 4096 request, <= 2048 response
u8  type                 REQUEST | RESULT | ERROR
u8  version              1
u16 reserved             must be zero
u64 request_id_be        exact nonzero echo
... type-specific bounded payload
```

`REQUEST` contains a host length (1..253), its exact bytes, a nonzero port and
an absolute monotonic deadline on the same host. It contains no credentials.
`RESULT` contains 1..32 fixed endpoints: family, 4 or 16 address bytes, exact
requested port and IPv6 scope. `ERROR` contains a closed enum and a bounded,
non-secret diagnostic. Strings are length-prefixed, never NUL-terminated on
the wire. Unknown type/version/flags, trailing bytes, overflow, truncation,
oversized frames, wrong identity and invalid endpoint forms fail closed.

EOF before one valid terminal frame, worker exit, signal death, broken pipe or
multiple terminal frames fail the request. The parent never reconnects or
silently retries using the compatibility provider when a hard provider was
required. Worker argv and environment contain no hostname or secret; the IPC
fd is the only request channel and unrelated descriptors are closed.

## Test gates required before public ABI

The resolver ABI remains private until a real provider proves all of:

1. fragmentation at every IPC byte boundary;
2. oversized, truncated, wrong-version and trailing-byte frames;
3. wrong request identity and malformed numeric endpoints;
4. worker crash before request, during lookup and during response;
5. deadline and concurrent cancellation physically reap the worker;
6. replacement workers accept later queries without result confusion;
7. queue and per-worker memory bounds under saturation;
8. TSan for parent ownership and ASan/UBSan for both sides;
9. Linux amd64/arm64 and macOS arm64 behavior.

## Extraction plan

- **R0 — current:** keep the seam and getaddrinfo compatibility provider private
  in Maelys HTTP. Prove validation and ownership with injected fakes.
- **R1:** implement a private worker executable and supervisor beside HTTP,
  using the draft envelope. Do not install a public header or promise MHRP/1.
- **R2:** integrate the same provider with a second real consumer, expected to
  be Egress or the MCP HTTPS connector, and reconcile lifecycle requirements.
- **R3:** only after both consumers pass the physical matrix, extract the
  dependency-free supervisor/provider into a `maelys-resolver` repository,
  freeze its ABI and protocol, and replace the private HTTP seam with the pin.

This sequence avoids creating a public resolver product around an interface
that has only one consumer and no process implementation today.
